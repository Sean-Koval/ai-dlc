- `knowledge records search --root <clone>` reads a knowledge repository in place, with no
  `KNOWLEDGE_REPO` or `--provider git` (KAN-494). On a terminal it prints a ranked, compact
  list (id, type, status, title, then the record's line, owner and evidence); piped or captured,
  as skills read it, it prints the JSON it always did, now ranked. `--format text|json` forces
  either. Source records are left out unless `--type source` is given.
- Record ids and ticket keys match in any case, in `knowledge why` and `records get`.
  `knowledge why KAN-241` answers with the decision derived from that ticket, not its Source
  record, and lists other records derived from the same source.
