- The reusable `knowledge-merge` workflow mints its GitHub App installation token on
  each run from the `app-id` input and `private-key` secret, scoped to the calling
  repository (KAN-522). A stored installation token expired within the hour. A plain
  `token` (a fine-grained personal token) still works as the fallback; with no
  credential the job skips with a notice, and with only one of `app-id` and
  `private-key` it fails. `knowledge init --customer` writes a caller that passes the
  `KNOWLEDGE_APP_ID` variable and the `KNOWLEDGE_APP_PRIVATE_KEY` secret.
