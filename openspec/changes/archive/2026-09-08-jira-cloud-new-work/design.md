## Authorized boundary
REST v3 only, via fixed api.atlassian.com/ex/jira/{cloud_id}. Require HTTPS bare atlassian.net site URL, explicit UUID cloud ID, authentication mode and named environment references. oauth_bearer accepts an externally managed access token. personal_scoped_token_basic accepts an approved personal scoped API token and email. No refresh/native credential extraction, token guessing or Data Center support. Recheck serverInfo Cloud/baseUrl and myself accountId before operations.

Use common WorkService publication/transition journals and finish gates. The adapter preserves the literal correlation in a separate ADF paragraph and an ai-dlc property in the create request. The property binds schema/correlation/operation/cloud/account/project/type. Fresh-read create identity/property/marker before success. Search the selected project using enhanced search/jql, consume every continuation token up to fixed budgets, reject warnings/repetition/incomplete identity/duplicates, and exact-match property plus marker. Eventual indexing and missing journals across machines do not prove absence or exactly-once creation; preserve existing uncertain-create no-retry behavior.

Require explicit distinct open/in_progress/closed/cancelled status IDs and disjoint closed/cancelled resolution IDs. Cancellation status/resolution takes precedence. Closed requires both configured successful status and resolution; unknown terminal outcomes remain unknown. Current transitions must target the selected status and yield one route or an explicit reviewed ID. Validate supported fields/required defaults/allowed IDs from current metadata before mutation, then fresh-read actual state. Do not retry an uncertain transition in one invocation.

Support a bounded field subset: string, finite number/integer, boolean, explicit ID objects, arrays of those, and ADF text documents for description/textarea. Unsupported required fields fail with field IDs only. Reserved create fields cannot override project/type/summary/description/correlation. Metadata is re-read before create; workflow validators may still refuse remotely.

Common onboarding discovers all accessible projects, standard issue types, type statuses, create fields and resolutions within shared finite budgets. Composite project:type IDs avoid merging one issue type across project contexts; selected status membership is checked against that pair. Existing reviewed create/transition field values are validated and retained, never guessed. Only common service saves/applies config, with no remote setup writes.

Remote links use deterministic scoped globalId and exact URL identity. Read before/after writes and preserve authored description. Existing matching links are left unchanged; conflicting globalId is refused. Link Issues permissions and workflow field/transition behavior remain live qualification gates. Plane and full parent TA/PT scope remain open.
