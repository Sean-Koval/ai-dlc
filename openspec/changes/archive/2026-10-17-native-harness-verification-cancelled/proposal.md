## Why

Rendered files are not proof that an installed coding client recognizes instructions, discovers selected skills or can authenticate a selected MCP server. Current Antigravity rendering emits a managed Markdown rule with a manual Always On instruction, whereas [current official rules documentation](https://antigravity.google/docs/rules/) specifies activation metadata for modular rules. This is a compatibility risk, not an observed explanation of the teammate's failure. The [product direction](../../../docs/product-direction.md) explicitly retains installed-client qualification as unverified.

## What Changes

- Define a version/edition/platform-bound native smoke procedure and evidence contract for explicitly selected supported clients.
- Report configured, rendered, recognized and authenticated separately, including missing, unknown and stale evidence.
- Resolve Antigravity rule activation by tested client edition/version, preserving authored content and ownership boundaries.
- Bind evidence to the effective-environment configuration/observation identities and record one instruction, one selected skill and one harmless selected MCP smoke outcome.
