# Version-bound native harness smoke verification

Priority: P1. Product owner: Sean Koval. Implementation owner: unassigned. Status: proposed for review; no native qualification or paid run has occurred.

## Problem and outcome

Rendered files do not prove a selected client loads instructions, invokes skills or uses authenticated tools. Current Antigravity modular-rule documentation requires activation metadata while repository guidance still prescribes manual Always On activation. Resolve the version-specific risk and define reproducible native smoke evidence without guessing why the teammate's original attempt failed.

## Authorized scope and technical recommendation

The user authorized specifications and detailed issues from the PM review. The proposed `agents verify` surface, evidence schema and version-scoped adapter/render flags are engineering recommendations, not implementation approval or proof of broad compatibility. Actual installed-client qualification remains #53.

## Acceptance

- NHV-01: Configured/rendered/recognized/authenticated remain separate. Verification defaults to procedure generation and bounded local evidence validation, with no native launch or account operation.
- NHV-02: One instruction marker, one selected skill invocation and one harmless selected MCP outcome are recorded independently, bound to complete EER identities, engine source, client edition/version, platform, fixture and adapter contracts. Enumeration alone is not invocation/authentication.
- NHV-03: Known version-scoped Antigravity schemas receive correct modular activation metadata with existing ownership preservation; unknown versions and conflicts remain unverified/refused. Root instructions do not prove modular activation.
- NHV-04: Changed source/client/platform/profile/guidance/fixture/adapter context invalidates exact-context evidence. Present-session authentication is not inferred from an older observation.
- NHV-05: No secrets/private paths/accounts/raw transcripts in shareable evidence. No paid calls or automated OAuth by default. Fixture tests are not live qualification.

## Dependencies and delivery

Depends on the effective-environment-report capability's schema-1 configuration and observation identity/completeness contract. Reuse existing harness adapters, renderer ownership and readiness integrations. No new MCP/hosted surface or orchestrator. Deliver helpers and procedure on supported hosts independently of native Windows implementation; #53 owns the installed-client/Windows walkthrough and actual evidence. Keep paid comparison #138 deferred.

## Failure and evidence expectations

Unsupported schema/version, missing render, stale identity, wrong marker, unavailable harmless tool and failed authentication have separate bounded reasons. Invalid evidence exits 2; missing/failed/stale scope exits 1; complete matching smoke scope exits 0 with operator-attested provenance. Include negative marker, version upgrade, edited-file preservation, malformed/oversized evidence and secret-sentinel tests. Native observations must record actual installed context and timestamp; absent account/host/cost permission stays pending without fabricated evidence.
