## Bounded design

Registry definitions distinguish existing compatibility connectors from declarative handlers. New handlers return complete account/resource discovery and a provider patch; they cannot choose filesystem writes through this interface. The common service resolves unique resource names/IDs, stores canonical IDs, rediscovers before apply, validates shared configuration, and owns exact source/runtime/work snapshots, exclusive saved plans, authored TOML rendering and locked apply. GitHub reuses these extracted primitives while retaining both established saved formats and Project creation journaling. Linear uses its existing canonical digest and replaceable saved-plan codec; this is an explicit remaining legacy extraction boundary, not a claim that all PT-02 persistence is unified.

Prefer extracting the accepted exact writer over converting Linear and GitHub to one new format; conversion risks weakening protections or breaking retained plans. Keep builtin compatibility call signatures and CLI options. Generic --select names normalize hyphens to underscores, reject duplicate/unsupported keys and never echo supplied values in validation errors. Declarative connection discovery requires schema1, complete=true, account identity and unique stable resource IDs. Definition callbacks remain trusted Python code, not executable configuration or a plugin loader.

No new provider lifecycle, remote writes for qualification, harness rendering, readiness redesign, machine enrollment, Confluence or parent archive. The exact writer retains its already documented bounded same-user-race semantics; do not claim new crash-atomic guarantees from extraction.
