## Why
Work uses Jira Cloud for new work. GitHub/capability support is already delivered; neither ticket migration nor Plane deployment is requested.

## What Changes
- Add the optional jira-cloud lifecycle kind and shared declarative onboarding handler.
- Bind explicit Cloud/site/account/project/standard issue type and approved externally managed bearer or personal scoped-token Basic authentication.
- Preserve exact correlation in ADF plus a same-create issue property, bounded complete reconciliation, explicit state/resolution mappings and current transition-field validation.
- Link PR/spec evidence with reconciled remote links through existing WorkService.

## Impact
New provider/onboarding/registration/guidance/tests and this bounded specification. No vendor branches in WorkService, CLI or provisioning; no migration, company API calls, package publication or parent completion.
