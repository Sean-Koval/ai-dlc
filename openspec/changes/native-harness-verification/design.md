## Evidence schema and manual procedure

Schema 1 evidence contains `schema_version`, both environment identities, `engine` safe provenance, `client` (`id`, `edition`, `version`), `platform` (`os`, `architecture`), `observed_at` UTC, `observer` as a nonpersonal logical role, `fixture_id`, `fixture_sha256`, `adapter_contract_id`, `adapter_contract_sha256`, `steps[]`, `auth`, `cost_authorization` (`not-required|authorized|pending`) and `limitations[]`. `auth` contains `state` (`verified|failed|not-assessed|not-applicable`), `observed_at`, `scope_checked` boolean and a bounded reason code; it contains no account identifiers. Each step has `id` (`instruction|skill|mcp`), selected logical artifact/tool ID, `expected_marker`, `observed_marker`, `result` (`passed|failed|pending|not-applicable`), and bounded `reason_code`. Evidence is operator-attested, not cryptographically proven client execution; that provenance is explicit in output. No free-form transcripts/screenshots, access tokens, account email, absolute path or account-manager dumps are accepted in the shareable artifact. Raw observations, if retained by the operator, remain private and are not automatically scanned or uploaded.

Use a small disposable fixture with deterministic benign markers. The instruction asks the client to include an innocuous project marker in its response. The selected skill is a reviewed fixture-compatible skill exposed through the same selected delivery path, with a distinct expected marker or prescribed harmless output; merely showing a filename is not a successful invocation. The MCP smoke uses one explicitly selected existing server/tool whose adapter declares it read-only and non-billable: list tools and, where safe, call a fixed harmless introspection tool and check its known shape/marker. Tool enumeration alone demonstrates discovery, not successful tool execution or authentication. If no suitable selected skill/server exists, mark that step not-applicable with a reason and report partial scope, never all-three qualification. Do not install or select extra providers to make the matrix green.

By default generate only the procedure and record pending steps. A human starts any interactive client session within their authorized account/cost settings. If a step needs billed model/provider usage, mark it pending until separately authorized; the helper must not initiate it. The procedure reports authentication separately: a successful authenticated harmless call may support verified authentication for the selected endpoint/scope at the observation time; an unauthenticated local MCP server records authentication not-applicable; a UI login indication or credential presence alone remains not-assessed. Do not infer which account an endpoint-shared OAuth cache uses. Provider-specific account confirmation remains manual and private; reports retain only whether the expected scope was checked.

## Invalidation and failure handling

Any change in either EER identity, selected client edition/version, engine artifact/source/dirty status, platform, profile/source pin, managed instruction/skill/MCP configuration, fixture digest or adapter contract digest makes prior exact-context evidence stale. A schema documentation change can mark a compatibility entry pending review; it does not rewrite historical evidence. Authentication observations are point-in-time, never a permanent readiness guarantee; an explicit later auth failure supersedes success, while no fresh check leaves authentication unassessed for the present session. Preserve historical timestamp/context and explain which input changed.

Missing local guidance is `render-missing`, digest mismatch is `render-stale`, unsupported edition/schema is `client-schema-unverified`, missing observation is `native-observation-pending`, wrong marker is `smoke-failed`, identity mismatch is `evidence-stale`, and authentication failure is `authentication-failed`. Malformed or over-1-MiB evidence is refused with safe bounded errors, never quoted raw. A failure in one step does not suppress independent results, mutate client configuration or retry paid work automatically.
