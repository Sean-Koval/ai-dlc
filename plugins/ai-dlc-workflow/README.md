# AI-DLC workflow plugin

One optional Claude Code plugin that carries AI-DLC's workflow guidance, team
skills and safety hooks. A team harness pins it as a single component, so a run
can be compared with and without it. AI-DLC authors the plugin; it does not
decide where it is enabled.

Everything in this directory except this README is generated by
`scripts/build_workflow_plugin.py` from `agents/skills/`, the shared AGENTS.md
guidance and `src/ai_dlc/harness/hook_shim.py`. Do not edit generated files;
change the source and rebuild. The `generated` required check runs the builder
with `--check`.

## What is inside

| Path | Content |
| --- | --- |
| `skills/ai-dlc-workflow/` | Provider-neutral workflow guidance as a skill; plugin `CLAUDE.md` files are not loaded |
| `skills/<team-skill>/` | discovery, prd-draft, needs-spec, spec-from-prd, review-inbox, handoff, document-review, document-organize, design-brief, design-evaluate |
| `hooks/hooks.json` | SessionStart, PreToolUse (`Bash\|exec_command`) and Stop hooks, exec form, 10 s timeout |
| `hooks/aidlc_hook.py` | Standard-library hook shim |
| `plugin.lock.json` | One digest per component and a `content_digest` over them |

Skills appear namespaced, for example `ai-dlc-workflow:needs-spec`. The personal
`day-start` and `day-end` skills are not included. When a repository also renders
its own unprefixed copies, the guide skill tells the agent to prefer those.

`plugin.json` sets `version` to `<engine>-r<revision>`. The builder increases the
revision whenever the content digest changes, so installed copies update only when
content changes. `metadata.content_digest` repeats the lock's digest; the pinning
harness records the source commit.

## Hooks

The shim delegates to `ai-dlc hook <event>` only when `ai-dlc` is on PATH,
`ai-dlc.toml` exists at the repository root, and the session is not in a hangar
sandbox (`HANGAR_WORKSPACE` or `HANGAR_JOB_ID` set). Otherwise:

- SessionStart prints one line saying lifecycle commands are unavailable, or
  nothing with `AI_DLC_HOOKS=quiet`.
- PreToolUse denies destructive shell commands (such as `rm`, `git reset --hard`,
  `git clean -f`, force or delete pushes) with exit 2 and allows everything else.
  It never applies the bound-push policy, so `git push` and `gh pr create` are
  not blocked.
- Stop does nothing.

The shim reads only the command text, never runs it, and writes nothing to disk.
A failing or slow delegate is treated as allow with a one-line note, so a hook
never wedges a session.

## Requirements and limits

- `python3` (3.10 or later) must be on PATH. There is no shell fallback. Native
  Windows plugin hooks are unsupported because exec form cannot substitute another
  interpreter name.
- Hangar's hardened `ask` and `deny-risky` turns drop `enabledPlugins` and
  `extraKnownMarketplaces`, so the plugin does not load in those turns. Compare
  arms in turn modes where plugins load, or have hangar mount the plugin through
  `CLAUDE_CODE_PLUGIN_SEED_DIR`.
- Turn marketplace `autoUpdate` off wherever the plugin is installed for an
  experiment, or the treatment can change mid-experiment. Seed marketplaces are
  always read-only with auto-update off.
- The plugin declares no MCP servers and carries no credentials or project paths.

## Enable and disable

`defaultEnabled` is `false`, so the plugin loads only where it is enabled.

- Local testing: `claude --plugin-dir plugins/ai-dlc-workflow` together with
  `--settings '{"enabledPlugins": {"ai-dlc-workflow@inline": true}}'`.
- Marketplace install: set `"ai-dlc-workflow@<marketplace>": true` under
  `enabledPlugins` in the scope you want, or run
  `claude plugin enable ai-dlc-workflow@<marketplace>`.
- Turn it off: set the same key to `false`, or `claude plugin disable`.
- Keep the plugin but silence its hooks: `AI_DLC_HOOKS=off`.

Check the package with `claude plugin validate --strict plugins/ai-dlc-workflow`.
