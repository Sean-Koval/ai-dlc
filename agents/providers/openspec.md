# OpenSpec provider guidance

Use OpenSpec to create and validate the project’s formal behavior changes. Keep
proposal, design, specification, and task artifacts together under
`openspec/changes/`; validate the named change before requesting review.

OpenSpec records specification evidence. It does not replace the project’s
required checks or completion gates.

Read project context and artifact rules from the configured OpenSpec change. Identify affected canonical docs during proposal/design; review them against code and tests before completion. Keep implementation tasks in the change task artifact and durable explanations in their existing owner documents.
